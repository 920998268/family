# 家庭打卡小程序 0.3.2 版本说明

**版本号：** v0.3.2
**发布日期：** 2026-09-12
**上一版本：** v0.3.1

---

## 版本概述

0.3.2 是**打卡数据云端化版本（M2-A）**。把长期停留在 localStorage 的
**饮食打卡**与**运动打卡**迁移到 uniCloud：新增两个云函数、三个集合、
一套前端映射层与轻量离线同步机制；运动模型扩展支持**有氧**；
饮食新增**常用食物**快捷选择。

同时收口了 v0.3.1 发布后累计的 11 项缺陷修复。

| 指标 | v0.3.1 | v0.3.2 |
|---|---|---|
| 单元测试 | 64 项 / 6 文件 | **394 项 / 24 文件** |
| 云端集合 | 3（families / family_members / uni-id-users） | **6**（+ diets / workouts / favorite_foods） |
| 云函数 | 3（family / member / register） | **5**（+ diet / workout） |
| type-check | 通过 | 通过 |

## 一、新增功能

### 1. 饮食打卡上云

- 新增 `diet` 云函数与 `diets` 集合，支持 `list` / `add` / `update` / `remove` 的**记录级 CRUD**；
- 记录以客户端生成的 `clientId` 为幂等键（前端就是记录 `id`），
  **按记录而非按天提交** —— 避免两人同时给同一天打卡时后写者整包覆盖前写者；
- 新增 `cloudMap` 映射层，统一处理云端 `null` 与前端 `undefined` 的换算。

### 2. 运动打卡上云 + **扩展支持有氧**

- 新增 `workout` 云函数与 `workouts` 集合，复用 `families` 的家庭归属鉴权；
- 运动模型在原有「力量（组数 / 次数 / 重量）」之外**新增有氧**：
  时长（必填）/ 距离（选填）/ 消耗热量（选填），力量与有氧共用一张表、由 `category` 区分；
- **老记录兼容**：历史训练记录没有 `category` 字段，读取时按「有组明细 = 力量」推断，
  不会因为字段缺失被校验器判非法而静默丢弃。

### 3. 常用食物快捷选择

- 新增 `favorite_foods` 集合，打卡时**自动沉淀**常用食物并按使用次数排序；
- 新增饮食表单的「常用」面板，一键带出名称 / 数量 / 营养值，支持删除。

### 4. 轻量离线能力（本地优先）

- 写入**先落本地**让界面即时生效，云端在后台异步推送；
- 新增待同步标记（`family.pendingSync.v1`）：推送失败保留标记，
  下次进入页面或回到前台自动补传；连续失败 5 次后放弃并告警；
- 读取为「**云端为准、本地兜底**」：本地缓存先渲染（秒开），
  云端结果回来后合并回写；
  **本地有待同步修改的记录以本地为准**，避免离线改的内容被云端旧值覆盖回去。

### 5. 运动表单与列表

- 运动表单顶部新增「类型」切换（力量 / 有氧），按类型展示对应字段；
- 列表展示改为「类型 · 汇总」，力量记录补上「N 组」，
  有氧记录展示「时长 · 距离 · 消耗热量」。

## 二、Bug 修复（共 11 项）

### v0.3.1 发布后「我的」模块回归（10 项）

- **P0-1** 个人档案只填必填项时保存失败（选填字段被错误地强制校验）
- **P0-2** 新用户换头像静默失败（Promise 异常被吞）
- **P1-1** 首页成员入口指向旧版成员页（字段少、不走云端）
- **P1-2** 云函数业务错误信息全部丢失（`msg` / `message` / `errMsg` 未统一兼容）
- **P1-3** 应用重启后云端档案恢复被跳过（`getMyStatus` 未回填 uid）
- **P2-1** 个人档案头像同步用了本地临时路径而非云存储地址
- **P2-2** `MemberAvatar` 不解析 `cloud://` 头像地址
- **P2-3** 成员详情预设手机号只写本地、不同步云端
- **P2-4** 成员详情手机号输入框交互冲突与初始化竞态
- **P2-5** H5 刷新后不恢复登录上下文（启动引导被条件编译限在微信端）

### 本版本新发现并修复（1 项）

- **云同步被永久静默跳过**：`isLoggedIn` 曾被写成 `computed(() => hasToken())`。
  `hasToken()` 读的是 uni storage（**非响应式**），该 computed 没有响应式依赖，
  首次求值后结果被永久缓存；而 `App.vue` 的 `onShow` 必然在**登录之前**触发一次
  云同步前置判断，把 `false` 缓存下来 —— 此后即使登录成功也永远判定为「未登录」，
  所有打卡云调用被静默跳过。表现为**「打卡一切正常、数据只在本地、云端没有也不报错」**。
  已改为普通函数（每次实时读 storage），并加源码守卫防止回退。

## 三、优化改进

1. **测试体系**：从 64 项扩到 394 项，覆盖双向字段映射、同步重试与合并、
   表单校验全分支、云函数纯逻辑、集合 schema 一致性；
2. **兼容守卫**：对「防止数据被静默丢弃」的关键逻辑（老记录兼容、待同步合并、
   竞态守卫）统一做**变异测试**验证守卫有效；
3. **文档体系**：新增 M2-A 需求与技术方案、可执行的部署与真机验收清单、
   故障排查手册；并新增**文档一致性守卫**测试（文档写到的路径 / 字段必须真实存在）；
4. **修复裸 uniCloud 隐患**：所有云调用统一走 `getCloud()`，
   避免被编译内联成框架静态快照（该快照会让云能力必然失败且报错文案极具误导性）。

## 五、升级与发布说明

### 1. 云侧部署（**必须在 HBuilderX 手工完成**）

支付宝云不支持 CLI 发行，以下操作无法通过命令行完成。
**逐项清单见 `docs/0.3.2-m2a-deploy-checklist.md`**，摘要：

| # | 上传项 | 说明 |
|---|---|---|
| 1 | 3 个 DB Schema | `diets` / `workouts` / `favorite_foods` |
| 2 | 公共模块 `common/checkin-shared` | **最容易漏**，漏传会导致两个云函数加载失败 |
| 3 | 云函数 `diet` | 饮食 + 常用食物 |
| 4 | 云函数 `workout` | 运动 |
| 5 | 5 条索引 | 含 3 条唯一索引（`familyId + clientId` 等），是幂等的数据库层兜底 |

> ⛔ **不要用「上传所有云函数、公共模块及 actions」**：
> 该操作会连带重传 `uni-config-center`，而 HBuilderX 的公共模块来源目录里
> 并没有 `uni-id/config.json`，重传会导致**所有登录/注册接口报
> `Invalid uni-id config file`**（本次发布过程中实际踩过一次）。
