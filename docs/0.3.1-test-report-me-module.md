## 四、缺陷清单

### 🔴 P0-1 个人信息档案在只填必填项时无法保存

- **位置：** `src/pages/me/profile.vue` → `save()`；校验逻辑 `src/utils/validation.ts:76-100`（`validateProfile`）
- **复现：** 「我的」→ 点姓名/箭头 → 个人信息档案 → 只填 *姓名 + 性别 + 家庭关系* → 点保存
- **现象：** 弹窗「保存失败：出生日期不合法；身高需要在 50 到 260 之间；当前体重需要在 10 到 500 之间；目标体重需要在 10 到 500 之间」，档案未保存
- **根因：**
  - UI 把出生日期 / 身高 / 体重 / 目标体重呈现为**选填**（无必填提示、无前置校验）
  - `save()` 把空值转成 `birthDate = ''`、`heightCm = Number('') === 0`、`currentWeightKg = 0`、`targetWeightKg = 0`
  - `validateProfile` 却要求 `birthDate` 必须是合法 `YYYY-MM-DD`、且身高/体重必须落在 50–260 / 10–500 区间，**未做选填兼容**
- **影响：** M1 核心链路受阻；首页「先完善个人信息档案」横幅将永远无法消除

### 🔴 P0-2 新用户在「我的」页更换头像静默失败

- **位置：** `src/pages/me/me.vue#saveAvatar()`（第 93–111 行）；触发点 `onChooseAvatar` / `onAlbumTap`
- **复现：** 尚未建立档案的账号 → 「我的」页 → 点头像（微信头像或相册）
- **现象：** 头像不保存、无任何 Toast、控制台出现未捕获的 Promise 异常
- **根因：** 无 profile 时构造的对象同样是 `birthDate: '' / heightCm: 0 / ...`，过不了 `validateProfile`；
  `profileStore.save()` 抛错，而 `saveAvatar` **没有 try/catch**，调用方也未 `await`，异常被静默吞掉
- **说明：** 与 P0-1 同根因，属于同一处修复的两个表现

### 🟠 P1-1 首页成员头像点击进入「旧版」家庭成员页

- **位置：** `src/pages/home/home.vue:108` → `goPage('/pages/me/family')`
- **现象：** 从首页点某个家庭成员，进入 `src/pages/me/family.vue`（旧页），而不是现行的
  `src/pages/family-setup/family-setup.vue`
- **影响：**
  1. 旧页表单**只有 姓名 / 角色 / 头像颜色**，没有 性别 / 身高 / 体重 / 生日 / 手机号
  2. 旧页直接调 `familyStore.add/update/remove`，**完全不走云端同步**（`stores/family.ts` 全部是本地 localStorage）
  3. 在旧页编辑保存，会把成员从云端视角"降级"为本地记录，且扩展字段丢失
- **对照：** `src/pages/me/me.vue:192` 的「我的家庭」入口指向 `/pages/family-setup/family-setup`，是**正确的**；
  说明问题仅出在 home.vue

### 🟠 P1-2 云端返回的业务错误信息全部丢失

- **位置：** `src/unicloud/index.ts:158-161`（`callFamily`）与 `:221-224`（`callMember`）
- **根因：** 前端读取 `result?.message`，但自研云函数统一返回 `{ code, msg }`（见
  `cloudfunctions/family/index.js:54,60,62`、`cloudfunctions/member/index.js:15,29,47`）
- **影响：** 「你已加入家庭，无法重复创建」「邀请码无效」「尚未加入家庭」「登录态无效或已过期」等
  全部退化为 `family 云函数 [xxx] 调用失败`，用户无法得知真实原因，排障困难
- **备注：** `uni-id-co` 原生云对象走的是 `errCode/errMsg` 另一套约定，不受影响

### 🟡 P2-1 个人档案头像同步云端时用了本地临时路径

- **位置：** `src/pages/me/profile.vue:208`（`familyStore.add`）与 `:247`（`syncProfileToCloud`），均使用 `form.avatarUrl`
- **对照：** 同一函数 `:191-192` 已算出 `cloudAvatar` 并正确用于 `profileStore.save`
- **影响：** 家庭成员列表 / 成员详情里显示的头像在清缓存或换设备后失效
  （即 0.3.1 bug#6「头像存永久 fileID」的漏网之鱼）

### 🟡 P2-2 `MemberAvatar` 组件不解析 `cloud://`

- **位置：** `src/components/MemberAvatar.vue:20` —— `<image :src="props.avatarUrl">` 直传
- **对照：** 0.3.1 bug#8 已为 `avatar-image` 增加 `cloud://` → `getTempFileURL` 解析，但 `MemberAvatar` 漏改
- **使用方：** `family-setup.vue:650`（传入 cloud fileID）、`home.vue:110`、`me/family.vue:160`
- **影响：** 微信端可能请求 500 不显示；H5 端必然不显示

### 🟡 P2-3 成员详情「选择绑定」预设手机号只写本地

- **位置：** `src/pages/me/member-detail.vue#savePresetMobile()`（第 92–96 行）
- **影响：** `familyStore.update` 为纯本地操作，预设手机号未同步云端 →
  换设备 / 清缓存后丢失 → 对方用该手机号登录时的 `autoBindByMobile` 自动关联失效

### 🟡 P2-4 成员详情手机号输入框交互冲突

- **位置：** `src/pages/me/member-detail.vue:250-262`（`@tap="showMobilePicker"`），
  及 `onLoad` 中 `setTimeout(..., 100)` 初始化 `presetMobile`
- **影响：** 点击输入框会先弹操作表，阻碍手动输入；`setTimeout` 初始化属竞态写法

### 🟡 P2-5 H5 端刷新页面不恢复登录上下文

- **位置：** `src/App.vue:9-11` —— `bootstrap()` 被 `#ifdef MP-WEIXIN` 包裹
- **影响：** H5 刷新后 `authStore.uid` / `familyId` 为空，`me.vue` / `home.vue` 的云端恢复兜底
  条件（`isLoggedIn && hasFamily`）不成立，恢复链路被跳过

## 八、附加修复：裸 `uniCloud` 编译为框架静态快照（运行时「临时URL解析失败」）

### 8.1 现象

运行时报错并原样显示了框架错误文案：

```
临时URL解析失败，尝试原样显示: <Error: uni-app cli项目内使用uniCloud需要使用HBuilderX的
运行菜单运行项目，且需要在uniCloud目录关联服务空间>
```

该文案具有极强误导性——它并非提示「你没关联服务空间」，而是**桩对象**被调用后的产物。

### 8.2 根因

在 uni-app CLI 项目里，前端源码中的**裸 `uniCloud.xxx()`** 会被编译内联为
`@dcloudio/uni-cloud` 的**静态导出快照**（产物中的 `t.Vs`）。该快照在模块首次求值时即已定型：

- 编译期未关联服务空间 → 快照是一个桩对象，其 `callFunction / getTempFileURL / uploadFile`
  方法先 `console.error(...)` 然后 `reject`，错误文案就是上面那句；
- 运行时 `initUniCloud()` 成功后会替换 `globalThis.uniCloud`，但**替换不到已被内联捕获的 `t.Vs`**。

于是无论初始化多成功，`uniCloud.getTempFileURL()` 永远命中桩对象，头像 `cloud://` 地址永远解析失败。

### 8.3 修复

| 文件 | 改动 |
|---|---|
| `src/unicloud/index.ts` | `getCloud()` / `isCloudReady()` 提升为导出；`initUniCloud()` 返回 `boolean` 并对缺失 `raw.init` 做防护；`init` 在 `raw` 上调用后同时赋给 `cloudInstance` 与 `globalThis.uniCloud` |
| `src/utils/upload.ts` | `resolveAvatarUrl` 改为 `getCloud().getTempFileURL(...)`；未就绪时提前返回并给出明确告警，不再触发框架桩报错 |
| `tests/avatar.test.ts` | 改为 mock `@/unicloud`；新增**源码级守卫**：扫描 `src/{pages,utils,services,stores,components,repositories,storage}`，禁止出现裸 `uniCloud.<method>()` |

约定：**前端所有云能力调用一律走 `getCloud()`，不得直接写裸 `uniCloud.xxx()`。**

### 8.4 验证证据

编译产物 `dist/build/mp-weixin/utils/upload.js` 修复前后对比：

